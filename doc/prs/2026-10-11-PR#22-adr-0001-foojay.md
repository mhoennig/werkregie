# PR#22: Temurin 25 Comes from Foojay, Not from the Build Environment

> **WARNING:** This document describes only the change applied in this PR.
> It may already be outdated once the next PR is merged.
> Historic PR documentation is not maintained along with new PRs; treat it as a snapshot.

## Related Links

- [werkregie PR#20](https://git.javagil.de/mi/werkregie/pulls/20): ADR 0001, Temurin 25 for all werk repositories.
- [werkator PR#62](https://git.javagil.de/mi/werkator/pulls/62): rejected Temurin baked into the rootfs.

## Problem

ADR 0001 puts Temurin 25 into Werkator's build environment, so that "no build downloads a JDK".
The reason is wrong: the builds on mih09 share one Gradle home, and Foojay downloads a JDK into it only once.
Temurin 21 lies there since 2026-09-17.

Werkator PR#62 had already rejected a Temurin baked into the rootfs:
each Java update would mean a new archive of about 425 MB, uploaded by hand.

`mi` decided on 2026-10-11 that Temurin 25 comes from Foojay, and the build environment stays as it is.

## Non-Goals

- No switch of a repository to Temurin 25 yet.

## Solution

- ADR 0001 gets a revision: Foojay 1.0.0 in each repository provides Temurin 25;
  the build environment keeps Debian's OpenJDK 21, which runs Gradle.
  The original text stays, as decisions are only added.
- Werkbaum: `#ops.jdk` loses the steps of the build environment.
- Version 0.9.1.
